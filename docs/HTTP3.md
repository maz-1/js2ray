# Experimental XHTTP over HTTP/3

XHTTP `option.httpVersion: '3'` uses Node's native HTTP/3 application, actual TLS ALPN `h3`, QPACK headers and DATA over UDP. It carries the existing VLESS/VMess bytes. It does not add another TLS layer, retry application bodies or fall back to TCP. `auto` still selects only HTTP/1.1 or HTTP/2. Traditional XHTTP uses `tlsSettings.alpn: ['h3']`; mixed h3/h2/http1 ALPN is rejected because no fallback semantics are implemented. Raw `network.type: 'quic'` continues to reject h3.

This target was developed against the unmodified QUIC build of Node main `62ca1bae5a2ba9fd63041464e90a6073e7dd0392`, using `--experimental-quic`. System Node v24.20.0 does not provide this API. The ordinary engines range is unchanged. There is no runtime download or external forwarding dependency. Ordinary imports and configurations do not load `node:quic` or emit its warning. Explicit H3 in any inbound/outbound, including unused and nested download settings, fails before Runtime/Manager resource creation with `Js2rayError`, `ERR_UNSUPPORTED`, phase `http3`. Parsing, normalization and CLI `check` remain independent of runtime capability.

Explicit TLS is required. CA and certificate-name verification default to enabled; only `rejectUnauthorized: false` (traditional `allowInsecure: true`) disables them. Route `host` is independent of TLS `serverName`. Concrete DNS SAN identities require the matching SNI. Certificate material may be inline or file based. Examples: [native client](../examples/vless-http3-client.json), [native server](../examples/vless-http3-server.json), [traditional client](../examples/vless-http3-v2ray-client.json).

`stream-one`, `stream-up`, `packet-up` and `auto` reuse XHTTP routing, padding, pairing, sequence and bounded buffering. For H3, auto uses stream-up. Stream-one and stream-up carry upload FIN and download EOF, including responses generated after upload EOF. Packet-up retains the existing XHTTP wire contract: ending the logical client cancels the session; packet requests do not encode a separate logical upload EOF. It supports ongoing duplex bytes, not an added packet EOF protocol. Split `downloadSettings` owns an independent pool; both endpoints must reach the same backend session. H3/H3 and mixed H3/H2 paths are tested using a local HTTP/2-to-H3 forwarding fixture, not an external proxy interoperability claim.

XMUX retains logical concurrency/client/reuse/request/lifetime accounting, real `version: '3'`, stream-local cancellation and GOAWAY retirement. Requests have bounded header/stream-credit deadlines, including the native `raw.opened` Promise. H3 control and QPACK have three unidirectional stream credits. Explicit `xmux.hKeepAlivePeriod` values other than `-1` are rejected; omitted H3 keepalive creates no HTTP/2 PING. Native finite idle timeout is 30 seconds. DATAGRAM, WebTransport, push and 0-RTT are outside this implementation. `ref`/`unref` does not configure native QUIC endpoint liveness because the pinned public endpoint has no such methods. XHTTP `sockets` counts TCP sockets, not UDP endpoints; listener H3 session/request counts are separate. Native endpoint baselines are checked directly in H3 tests. The generic TCP `connection`/`secureConnection` inbound handshake watcher is not used by H3; no parity claim is made for those TCP handshake metrics.

Normal completion waits for actual EOF/writer completion and native closure before releasing request ownership, within a cleanup deadline. Explicit pool/runtime and server destruction sends application `H3_NO_ERROR` (`0x100`; this Node exports no public H3 error constants) and closes the local endpoint. RESET/STOP_SENDING abort the affected request, without killing siblings. DNS, handshake, response-header, stream-credit, initial server-header and rejected unfinished request deadlines are finite. Public writer Promises are owned; `body`/`setBody` and global rejection handlers are not used.

Shared H3 listener rotation rejects changed native connection/window/handshake or other captured limits with `ERR_ROTATION`; use a new listener for those changes. Paths, credentials and concrete DNS SAN certificates can rotate while old sessions drain. The pinned native `setSNIContexts('*')` cannot replace the default identity. Therefore replacing a wildcard/default identity is explicitly rejected during prepare; static wildcard/default identities remain usable. Concrete DNS SAN listeners use replaceable named SNI contexts. Invalid TLS material is checked before commit. HTTP/1 and HTTP/2 rotation behavior is unchanged.

See `test-results/http3-implementation/FINAL-REPORT.md` for exact final results, failures and reference-core evidence. Earlier raw QUIC FIN and VMess failures remain independently recorded in `test-results/quic-implementation`; passing H3 tests do not resolve them. Package installation remains unverified; the previously interrupted install has not been retried.
